# Plan: Nettoyage de l'historique Git et push (branche `notif`)

## Contexte
- Branche courante : `notif` (6 commits locaux, diverge de `origin/main`)
- Dépôt local : 3,3 GB (objets Git : 1,04 GB)
- Problème : Push bloqué car l'historique contient `apps/backend/spark-3.5.0-bin-hadoop3.tgz` (400 MB) et caches `.next` (70-150 MB), dépassant la limite GitHub de 100 MB
- La branche `notif` ne contient pas ces fichiers dans ses commits récents, mais ils sont dans l'historique global (commits anciens d'autres branches)

## Objectif
Supprimer définitivement les fichiers volumineux de **tout l'historique Git** (toutes branches) tout en **préservant les commits de la branche `notif`**, puis pousser vers `origin/notif` avec force (historique réécrit).

---

## Étapes d'exécution

### Étape 1 – Créer un backup local de la branche `notif`
```bash
cd /home/albert/agregateurdepaiement
git branch backup-notif-$(date +%Y%m%d-%H%M%S) notif
echo "✅ Backup créé. Pour vérifier : git branch | grep backup"
```
*Sécurité : une branche de sauvegarde locale est créée avant toute opération destructrice.*

### Étape 2 – Supprimer les fichiers non-versionnés volumineux (node_modules, caches)
```bash
cd /home/albert/agregateurdepaiement

# Supprimer tous les node_modules (ils seront réinstallés plus tard)
find . -type d -name "node_modules" -exec rm -rf {} + 2>/dev/null || true

# Supprimer les caches Next.js résiduels
find . -type d -name ".next" -exec rm -rf {} + 2>/dev/null || true
find . -type d -name "dist" -exec rm -rf {} + 2>/dev/null || true
find . -type d -name "build" -exec rm -rf {} + 2>/dev/null || true

# Afficher l'espace libéré
du -sh .
```
*Résultat : le répertoire de travail passe de 3,3 GB à ~300-400 MB.*

### Étape 3 – Vérifier/installer `git-filter-repo`
```bash
# Vérifier si déjà installé
which git-filter-repo 2>/dev/null && echo "✅ git-filter-repo déjà installé" || {
    echo "⚠️  git-filter-repo non trouvé. Tentative d'installation..."
    # Essayer pip3 (Python)
    if command -v pip3 &>/dev/null; then
        pip3 install --user git-filter-repo
        export PATH="$HOME/.local/bin:$PATH"
    # Sinon apt (Debian/Ubuntu)
    elif command -v apt &>/dev/null; then
        sudo apt update && sudo apt install -y git-filter-repo
    else
        echo "❌ Impossible d'installer git-filter-repo automatiquement. Veuillez l'installer manuellement:"
        echo "   pip3 install --user git-filter-repo"
        exit 1
    fi
}
which git-filter-repo || { echo "❌ git-filter-repo toujours pas trouvé après installation. Abandon."; exit 1; }
```
*Note : `git-filter-repo` est l'outil recommandé (rapide, sûr). Il crée automatiquement une sauvegarde dans `refs/original/`.*

### Étape 4 – Filtrer l'historique pour supprimer les fichiers volumineux
```bash
cd /home/albert/agregateurdepaiement

# Afficher les fichiers qui vont être supprimés de l'historique
echo "📋 Fichiers à purger de l'historique :"
echo "   - apps/backend/spark-3.5.0-bin-hadoop3.tgz (~400 MB)"
echo "   - apps/dashboard/.next/cache/ (~70-150 MB)"
echo "   - apps/b2b-dashboard/.next/cache/"

# Lancer le filtre (supprime ces chemins de TOUS les commits)
git filter-repo \
  --invert-paths --path apps/backend/spark-3.5.0-bin-hadoop3.tgz \
  --invert-paths --path apps/dashboard/.next/cache \
  --invert-paths --path apps/b2b-dashboard/.next/cache \
  --invert-paths --path apps/b2b-dashboard/.next \
  --force

echo "✅ Filtrage terminé."
```
*Explication : `--invert-paths` signifie "exclure ces chemins", c'est-à-dire les supprimer de l'historique. Tous les autres fichiers (y compris les commits de `notif`) sont conservés.*

### Étape 5 – Vérifications post-filtrage
```bash
cd /home/albert/agregateurdepaiement

# 1. Vérifier que les fichiers volumineux ne sont plus dans l'historique
echo "🔍 Vérification que les fichiers sont bien supprimés..."
git rev-list --all | git ls-tree --stdin -r -t --name-only 2>/dev/null | grep -E "(spark-3\.5\.0|\.next/cache)" && echo "❌ ATTENTION : certains fichiers sont encore présents !" || echo "✅ Aucun fichier volumineux trouvé dans l'historique"

# 2. Vérifier la taille des objets Git
echo "📦 Taille des objets Git :"
git count-objects -vH

# 3. Vérifier que la branche notif et ses commits sont toujours là
echo "🌿 Branche notif :"
git log --oneline notif | head -5
echo "✅ notif existe toujours avec $(git rev-list --count notif) commits"

# 4. Vérifier l'état du working tree
git status --short
```

### Étape 6 – Nettoyage final des objets orphelins
```bash
cd /home/albert/agregateurdepaiement

# Supprimer les objets non référencés (anciens blobs supprimés)
git reflog expire --expire=now --all
git gc --prune=now --aggressive

echo "✅ Nettoyage terminé."
git count-objects -vH
```

### Étape 7 – Push vers origin (force-with-lease)
**⚠️  IMPORTANT** : Cela va réécrire l'historique distant. Si d'autres personnes ont clones le dépôt, elles devront re-cloner ou reset.
```bash
cd /home/albert/agregateurdepaiement

# Vérifier la remote
git remote -v

# Vérifier les divergences
echo "📊 Branche notif vs origin/notif :"
git log --oneline --graph --all | head -20

# Pousser avec --force-with-lease (plus sûr que --force)
echo "🚀 Push en cours..."
git push --force-with-lease origin notif

if [ $? -eq 0 ]; then
    echo "✅ Push réussi ! La branche 'notif' est maintenant à jour sur GitHub."
else
    echo "❌ Échec du push. Vérifiez le message d'erreur ci-dessus."
    echo "   Causes possibles :"
    echo "   - La branche distante a été mise à jour par quelqu'un d'autre"
    echo "   - Problème de permissions"
    echo "   - Fichiers encore trop volumineux"
    exit 1
fi
```

### Étape 8 – (Optionnel) Nettoyer les références de backup de filter-repo
*À faire SEULEMENT après avoir vérifié que tout fonctionne bien sur GitHub et que tu as un backup local de `notif`.*
```bash
cd /home/albert/agregateurdepaiement

# Lister les refs originales (backup créé par filter-repo)
git for-each-ref --format='%(refname)' refs/original/

# Si tout va bien, les supprimer pour réduire la taille finale
git for-each-ref --format='%(refname)' refs/original/ | xargs -n 1 git update-ref -d 2>/dev/null || true
git reflog expire --expire=now --all
git gc --prune=now --aggressive

echo "✅ Nettoyage des backups terminé. Taille finale :"
du -sh .
```

## Scénarios d'erreur et solutions

| Erreur | Cause probable | Solution |
|--------|----------------|----------|
| `git-filter-repo: command not found` | Non installé | Relancer Étape 3, installer via `pip3 install --user git-filter-repo` |
| Push refusé : "non-fast-forward" | Origin a changé | `git fetch origin && git rebase origin/notif` puis retenter le force-push |
| Erreur "detached HEAD" après filter-repo | Branche orpheline | `git checkout notif` (doit exister) |
| Fichiers Spark toujours présents après filter-repo | Chemins incorrects | Vérifier les chemins avec `git log --all --oneline --name-only | grep spark` |

## Risques et atténuations

| Risque | Impact | Atténuation |
|--------|--------|-------------|
| Perte de commits de `notif` | Élevé | Backup local créé en Étape 1 ; filter-repo conserve tous les commits sauf les fichiers ciblés |
| Collaborateurs bloqués | Moyen | Les notifier de faire `git fetch && git reset --hard origin/notif` après le push |
| Corruption du dépôt local | Élevé | Backup local + filter-repo crée `refs/original/` (restaurable via `git reflog`) |
| Push échoue (taille encore trop élevée) | Moyen | Vérifier Étape 5 ; peut-être d'autres fichiers volumineux cachés (ex: `apps/dashboard/out/`) |

## Commandes de restauration (urgence)

Si quelque chose tourne mal après le filter-repo mais avant le push :
```bash
# Restaurer depuis les refs originales (backup automatique de filter-repo)
git reflog expire --expire=now --all  # Rendre les reflogs visibles
git log --all --oneline --decorate --graph  # Trouver le commit original

# Pour restaurer complètement l'état avant filter-repo :
git reset --hard refs/original/refs/heads/notif
# (ou la branche concernée)
```
