# Fix Payment System Database Issues

## Problem Analysis
The payment system is failing due to database column naming mismatches across multiple models:

1. **PaymentAttempt table column mismatch**: Database columns are snake_case but model was incorrectly configured
2. **WebhookEvent table column mismatch**: Database has `createdAt` (camelCase) but global `underscored: true` expects `created_at` (snake_case)
3. **CinetPay transaction_id issue**: The `transaction_id` field is missing from CinetPay payload due to field mapping issues
4. **Provider selection issues**:
   - Maviance provider routes still exist in database despite being commented out in code
   - CinetPay API calls failing due to missing required fields
   - Kkiapay health checks failing

## Root Cause
- Database was created with inconsistent column naming (mix of camelCase and snake_case)
- Global Sequelize config has `underscored: true` expecting snake_case columns
- Some tables have camelCase timestamp columns (`createdAt`) instead of snake_case (`created_at`)
- PaymentAttempt model field mapping was incorrect

## Solution Plan

### Phase 1: Fix Model Column Naming Issues
1. **Fix PaymentAttempt model** - Revert field names to camelCase, set `underscored: false`
2. **Fix WebhookEvent model** - Set `underscored: false` to match camelCase database columns
3. **Update service methods** to use correct field accessors

### Phase 2: Clean Up Provider Routes
1. **Remove Maviance routes** from database (completed)
2. **Update provider health checks** to handle failures gracefully
3. **Fix CinetPay payload** to ensure `transaction_id` is included

### Phase 3: Test and Validate
1. **Test payment initialization** with working providers
2. **Test webhook processing** for invoice sending
3. **Verify CinetPay payload** includes all required fields
4. **Check provider failover** logic

## Implementation Steps
1. Set `underscored: false` on WebhookEvent model
2. Fix PaymentAttempt model field definitions and accessors
3. Add debugging to verify transactionNumber is set correctly
