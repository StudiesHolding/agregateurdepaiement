# Fix Payment System Database Issues

## Problem Analysis
The payment system is failing due to database column naming mismatches and provider issues:

1. **PaymentAttempt table column mismatch**: Database columns are snake_case but model field definitions were incorrectly changed to snake_case instead of keeping camelCase (Sequelize handles the conversion when `underscored: true`)

2. **CinetPay transaction_id issue**: The `transaction_id` field is missing from CinetPay payload because `attempt.transactionNumber` is undefined due to incorrect field mapping

3. **Provider selection issues**:
   - Maviance provider routes still exist in database despite being commented out in code
   - CinetPay API calls failing due to missing required fields
   - Kkiapay health checks failing

## Root Cause
- PaymentAttempt model field names were changed to snake_case, but with `underscored: true` globally, Sequelize expects camelCase field definitions
- Maviance routes exist in DB but provider implementation is missing
- CinetPay requires `transaction_id` field which is not being sent due to undefined `transactionNumber`

## Solution Plan

### Phase 1: Fix PaymentAttempt Model Field Definitions
1. **Revert field names** in PaymentAttempt model back to camelCase (Sequelize handles snake_case database columns automatically with `underscored: true`)
2. **Update service methods** to use correct field accessors

### Phase 2: Clean Up Provider Routes
1. **Remove Maviance routes** from database (already completed)
2. **Update provider health checks** to handle failures gracefully
3. **Fix CinetPay payload** to ensure `transaction_id` is included

### Phase 3: Test and Validate
1. **Test payment initialization** with working providers
2. **Verify CinetPay payload** includes all required fields
3. **Check provider failover** logic

## Implementation Steps
1. Revert PaymentAttempt model field names to camelCase
2. Update PaymentAttemptService methods to use camelCase accessors
3. Add debugging to verify transactionNumber is set correctly
4. Test payment flows end-to-end

## Risk Assessment
- **Low risk**: Changes are isolated to model field definitions
- **Data integrity**: No data loss, only field accessor fixes
- **Backward compatibility**: Aligns with Sequelize conventions
